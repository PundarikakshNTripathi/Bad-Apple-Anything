# ADR-0007: No copyrighted source media in version control; synthetic fixtures only

Status: Accepted
Date: 2026-08-10
Deciders: project owner

## Context

The first deliverable's stated purpose is processing a specific
copyrighted source video and its audio track, supplied locally by the
project owner for personal, non-distributed, transformative use, which
is a reasonable posture under fair use style analysis even though that
determination is fact-specific and this document is not legal advice.
That posture applies to the project owner's local, private use of the
tool. It does not extend to the project's git repository, which is a
different context: a repository is the kind of artifact that tends to
get pushed to a remote (GitHub), potentially made public, forked, and
redistributed independent of the original owner's intent, none of which
is contemplated by a personal fair-use analysis.

Separately, and regardless of the copyright question, committing large
binary media files into git is poor repository hygiene: it bloats clone
size permanently (git history does not shrink when a file is later
deleted), and provides no diff-ability benefit the way text source does.

## Decision

The source video and any copyrighted audio/video asset the tool is
pointed at are never committed to version control, under any
circumstance. This is enforced two ways: `assets/` and `out/` are listed
in `.gitignore` at the repository root, and CI runs a repository hygiene
check (QA/Test Plan section 6) that scans staged and historical commits
for common video/audio file extensions above a small size threshold and
fails the build if any are found outside of an explicit allowlist (there
is no allowlist entry for `assets/` or `out/`).

All automated tests, including the ones that must exercise the full
ingestion-to-render-to-encode pipeline, run against synthetic fixtures
generated by code checked into the repository (for example, the
synthetic moving-subject clip already used to validate the matting
approach during initial prototyping), never against the real reference
video. A test that only passes when run against the specific copyrighted
source file is not an acceptable test in this project, both because it
cannot run in CI without that file present, and because it would create
pressure to add the file to the repository or to CI's environment, which
this ADR forecloses.

## Consequences

Positive: the repository itself carries no copyright exposure regardless
of what the project owner does locally, and the CI hygiene check makes
this a structurally enforced property rather than a matter of discipline
that could lapse. Test fixtures being synthetic and code-generated also
means they are trivially regenerable and versionable as text (the
generator code), not as opaque binary blobs.

Negative: synthetic fixtures cannot fully substitute for validating
against real, complex footage; the QA/Test Plan's manual QA checklist
(section 7) explicitly includes a step where the project owner runs the
pipeline against the real local asset outside of CI and visually verifies
the result, precisely because automated tests structurally cannot cover
that case.

## Revisit triggers

None anticipated. This is treated as a hard invariant of the project, not
a default subject to reconsideration; a change would require a separate,
deliberate ADR explicitly superseding this one with a clearly articulated
reason, not an incidental change made while working on an unrelated
phase.
